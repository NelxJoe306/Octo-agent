# Octo 话题地图

终端是 Octo 的主入口。Web 只展示当前终端会话的话题树与消息记录，不提供聊天、模型配置或工具执行。

## 打开

首次构建，在 `D:\Octo\web` 执行：

```powershell
npm ci
npm run build
```

启动终端：

```powershell
cd D:\Octo
.\.venv\Scripts\octo.exe
```

在运行中的终端输入 `/map`。它会打开附着当前 `CodingSession` 的浏览器窗口，使用动态本机端口。不要直接双击 HTML 或用普通静态服务器代替 `/map`。

关闭浏览器不影响终端任务；退出终端会关闭接口。终端内新建或恢复会话时，已打开的话题地图随之更新。刷新页面后继续使用当前窗口保存的连接信息。

## 使用

- 地图按深度分层，用父子连线区分主干和分支，可点击「适应窗口」。
- 进入话题在顶部打开标签，重复访问复用标签；可关闭标签并随时返回地图。刷新后从地图重新开始。
- 点击节点打开分支标签并定位到该分支最新记录；进入分支或切换标签即同步终端当前位置。
- 新建子话题、从消息建立子话题和重命名都由 Python 写入 SQLite。新建后打开该分支并同步终端当前位置。
- 当前请求与排队输入在提交时冻结话题。生成中切换话题，不改变已提交请求的归属。
- 消息中的「复制」复制文本；子话题中的「定位原文」按稳定消息 ID 回到讨论起点。
- 支持搜索、折叠、缩放，以及拖拽/键盘调整树和记录之间的分隔条。窄窗口通过页签切换树与记录。
- 记录每页最多 100 条，可以查看更早记录并回到最新。工具调用和图片等非文本内容目前仅显示文本或占位提示；完整生成过程继续在终端查看。

终端也可以独立操作：

```text
/topic-list
/topic-new 压缩策略
/topic-use <话题ID>
/topic-rename 新名称
/map
```

模型、API Key、OAuth、推理强度与工具支持继续使用原有终端能力和本机配置。Web 不读取凭据，也不调用模型。

## 开发与验证

```powershell
npm test
npm run typecheck
npm run build
```

`npm run dev` 只用于开发静态页面；真实会话接口由终端 `/map` 提供。运行时使用静态导出 `out/`，不需要另起 Node 服务。

Python 检查使用临时目录与假模型：

```powershell
cd D:\Octo
.\.venv\Scripts\python.exe -B -m unittest tests.sessions.test_topics -v
```

## 实现位置

- `src/octo_agent/session/topics.py`：话题操作、稳定消息定位、请求与消息原子归属。
- `src/octo_coding/session.py`：冻结请求、排队归属、话题 reminder 与事件。
- `src/octo_coding/topic_web.py`：附着现有会话的本机 HTTP/SSE 接口。
- `src/octo_coding/tui/app.py`：话题状态提示、`/topic` 和 `/map`。
- `web/app/page.tsx`、`web/lib/topic-map.ts`：视图与响应校验。
- `web/styles/tokens.css`、`web/app/globals.css`：主题、布局与动态状态。

更详细的设计见 [话题地图设计](docs/topic-map.md)。

## 快捷分支与消息显示

顶部的分支选择器可直接切换所有分支；「新建分支」从正在查看的话题创建并立即切换，先使用默认名称，随后可重命名。消息下方的创建按钮以该消息为锚点。创建与选择写入同一 SQLite 事务，不调用模型。主干保持独立身份。

终端使用 `/topic-list`、`/topic-new <标题>`、`/topic-use <唯一名称或完整ID>`、`/topic-rename <标题>`；`/topic-use main` 返回主干。名称重名时要求明确 ID。

回答支持 Markdown 标题、列表、表格、链接、代码块和 KaTeX 公式（`$...$`、`$$...$$`、`\(...\)`、`\[...\]`）；用户输入与工具输出保留纯文本。复制保留原文。原始 HTML 不执行，外部图片显示为链接，公式资源随静态构建提供，不依赖 CDN。

顶部合并会话与连接状态，分支快捷入口固定显示，标签区域独立横向滚动；窄窗使用地图/消息标签切换，宽屏保留可拖拽树窗口。


点击历史节点只定位该轮记录，不再把它当作消息列表的末尾。向下滚动接近底部时自动加载同一分支的后续记录，每页最多 100 条；也可点击「加载后续记录」。向前加载会保留已经加载的后续内容及阅读位置，刷新不会把视图拉回旧节点。「回到最新记录」可直接跳到分支末尾。更新后需重启终端后再打开 `/map`，以使用新的双向分页接口。
