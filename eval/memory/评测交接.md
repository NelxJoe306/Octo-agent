# Octo 跨会话记忆评测交接

评测日期为 2026-11-15，Octo 基线为 `bf50f9d`，本机 DeepSeek 提炼模型 ID 为 `deepseek-flash`。问题是，用户在会话 A 说过的话，哪些会被持久化，以及哪些会在会话 B 再次进入模型输入？

## 实际跑法

1. 固定 [20 条 JSONL 样本](cases.jsonl)，其中 9 条要求新增偏好，1 条要求覆盖，10 条要求忽略。每条包含类别、分批输入、各消息的角色、预期动作和探针。项目事实的隔离由仓库既有测试覆盖，未加入本次 20 条计数。
2. 每次每例新建临时目录及空 SQLite，创建 source 会话并按顺序追加原始消息。工具输出例保留助理调用和工具结果，助理猜测例保留说话人身份。写入端直接追加消息，以免主模型的自由回复改变测试输入。
3. 每批调用真实的后台 MemoryRuntime，使用 `notify(force=True)` 强制触发提炼。默认消息阈值为 32。等待 worker 空闲后检查后台错误和未处理来源，再查询包含失效记录的事实集合。写入和提炼均经过生产实现。两条更新相关样本各有两批，第一批先建立“英文提交信息”。其余 18 条各有一批，每轮共 22 次提炼。
4. 使用同一数据库、不同 session ID 打开新的 CodingSession。发送不含目标答案的探针，通过记录型主模型取得第一次真实请求，解析请求尾部的 Stored user preferences 段。探针回复使用固定值，评分只使用发送前的内容。
5. 三轮按固定顺序串行执行。真实网络调用只用于提炼，模型窗口参数为 8192，采样参数沿用适配器默认值，未固定 seed 或不可变模型快照。没有按结果调整提示词或重跑择优。

## 评判方法

- **召回**需要有效记录类型为 preference、引用预期用户消息、目标值命中，且该记录的 ID 和正文进入新会话。自动规则使用中英文正则。语义复核再检查实际文本的主体、方向和范围。
- **误记**指应忽略的输入相对于基准状态新增或改变了记忆。误写为普通 fact 也计入。另统计其中进入新会话的错误偏好。
- **覆盖**还要求第一批已建立英文偏好，第二批把旧记录标为 superseded，指向新记录。新请求中只有新记录。若新记录正文说明“不再使用英文”，它仍然是一条正确的中文偏好。
- **错误**单独统计。未处理来源、后台异常、未建立种子偏好或探针失败不能当成正确忽略。本次 60 次用例执行中为 0。
- **稳定性**按同一输入三次的判定统计。比较通过/失败时为 19/20。进一步区分错误写成 fact 还是 preference，以及它有没有注入时为 18/20。判断的是行为一致性，未要求自然语言措辞逐字一致。

## 结果

| 指标 | 第一轮 | 第二轮 | 第三轮 |
|---|---:|---:|---:|
| 自动判定的跨会话召回 | 10/10 | 9/10 | 10/10 |
| 复核注入文本后的跨会话召回 | 10/10 | 10/10 | 10/10 |
| 应忽略样本中发生误记 | 1/10 | 2/10 | 2/10 |
| 应忽略样本中错误偏好进入新会话 | 1/10 | 1/10 | 1/10 |
| 覆盖成功 | 1/1 | 1/1 | 1/1 |
| 提炼调用 | 22 | 22 | 22 |
| provider 报告的总 token | 8,979 | 9,020 | 9,009 |
| 20 例耗时之和（秒） | 31.57 | 29.55 | 29.92 |

共 66 次提炼，27,008 token，平均约 409 token/次。逐例耗时之和为 91.04 秒，包含临时库、后台任务和本地探针，不能当作模型单次延迟。按全部重复执行计，误记为 5/30（16.7%），其中 3/30 进入了新会话。这是 10 条负例各跑三次。

## 三个值得写进 README 的观察

1. 临时借电脑三次都落了库。第一轮虽然生成的记忆正文还保留了 “one-off request”，却被分类为 preference，因而注入了下一会话。其余两轮分类为 fact，仅检查新会话会漏掉这两次误写。
2. “这次用 uv 复现同事的问题”在后两轮被存为偏好并注入，第一轮正确忽略。仅看关键词 uv 无法区分工具选择的有效期。
3. 第二轮 p-examples 已正确写入并注入 “The user prefers explanations of concepts to start with examples.”。固定规则没覆盖 “start with examples”，所以自动分为 9/10。语义复核由本次执行评测的助手完成，未做独立双人标注。原始分保留供复查。

## 复现与证据

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.memory.test_memory_eval -q
.\.venv\Scripts\python.exe eval/memory/run.py --model deepseek-flash --runs 3 --output memory-run.jsonl
```

第一条只运行四项离线回归，包括误写 fact、后台异常、正确覆盖和错误并存。它们已随 Python 全量 165 项通过。第二条需要本机配置 DeepSeek 并产生 API 用量。输出路径须是新文件，脚本同时生成逐例 JSONL 和 CSV。每条 JSONL 的 snapshots 保存逐批数据库状态，recalled 保存发送给主模型的偏好，usage 和 seconds 可用于复算开销。

[评测脚本](run.py) · [固定样本](cases.jsonl) · [60 条逐例原始结果](deepseek-flash-2026-11-15.jsonl) · [离线测试](../../tests/memory/test_memory_eval.py)

每例最多一个有效偏好。当前实现按预算加载有效偏好，评测覆盖持久化和跨会话注入，没有量到海量记忆竞争预算时的相关性排序、模型最终是否遵从偏好，或真实对话中的误记发生率。
