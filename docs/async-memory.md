# 异步记忆提炼与偏好召回

本切片沿用已确认的独立后台提炼思路：主会话只通知后台任务，worker 先把范围写入 SQLite，再独立调用模型。默认沿用当前 provider/model，跨会话自动召回仅限用户明确表达的偏好。通用事实继续保留来源，不推断尚未确认的项目/环境适用范围。

## 配置与触发

默认启用。读取 OCTO_HOME 下 settings.json 的 memory 对象，沿用本机模型配置及凭据，无需另填 Key。示例：

```json
{"memory":{"enabled":true,"message_threshold":32,"request_timeout":60,"close_timeout":3}}
```

message_threshold 为 1–1000 的消息数，默认 32，统计原始 User/Assistant/Tool 消息，不含压缩摘要和自定义日志。request_timeout 为 1–600 秒，close_timeout 为 0.05–30 秒。未知字段和无效值会在加载配置时失败。enabled=false 同时关闭新入队、后台处理和自动召回；OCTO_DISABLE_MEMORY=1 可临时关闭本地默认配置，0 沿用文件配置。SDK 显式 CodingSessionConfig.memory_settings 优先，也可注入 memory_extractor 供独立提炼服务或测试使用。

达到阈值、用户消息含“记住/更正/纠正/忘掉/remember/forget/correct”等触发词，或正常关闭会话时处理尾部。触发词只决定是否尝试提炼，不代表必须新增事实。启动会重新检查已落盘原文，因此明确记忆请求不依赖进程内标记。正常退出先保存尾部待处理水位，再有限等待网络请求；已有任务未完成时也保留尾部意图，前一个范围提交后再按序入队。强制终止依靠已入队任务的租约恢复，尚未入队的原文在恢复该会话时重新检查。

## 后台处理与恢复

实现位于 src/octo_memory/runtime.py、memory_extraction.py。worker 使用 MemoryStore 的任务、令牌、原子收据及 schema 6 待处理水位；不会把模型提炼调用放进主 ReAct 循环。支持接管同一数据库中已就绪的持久任务，多个进程由租约竞争。每批最多 32 条原始消息，按当前模型窗口缩小输入批次；已有事实过多时减少提供的事实，不裁掉本批原文后冒充已读取。单条原文过大则保留错误任务，不推进进度。

原文输入明确限于持久消息的可见文本；不读取图片、thinking、摘要或外置工具产物正文。原始工具消息若只含产物预览，后台实际读取的也只是该预览。每条输入带消息/会话 ID、原始时间戳和请求/话题身份；事实来源由 MemoryStore 再校验。偏好必须引用真实用户消息；模型返回的更正目标还必须是实际提供给它的有效事实 ID。

静态配置 provider 和扩展 provider 都创建独立后台实例，使用独立 memory:job_id 请求身份，空工具列表，完成后关闭实例。SDK 直接注入且无可重建配置的自定义 provider 复用实例，但仍是独立请求，不修改其主请求预算；这种 provider 应支持并发 stream_response，或由调用方注入独立 memory_extractor。

后台输入/输出也有预算门控：独立实例输出预留最多 2048，同时服从原生输出上限和窗口封顶；预算也计入 provider 的额外系统输入及更小的原生窗口，安全余量 256；超窗不发送。要求完整 JSON 操作数组，最多 32 项；格式错误、未完成输出、工具调用、非法来源及无效更正目标均不落事实。错误记录在任务上并显示在 /session 的 Memory 状态，主聊天继续。失败至少间隔 30 秒重试，同一 runtime 对单任务最多自动失败 3 次；修正配置并重新打开会话可再次尝试，学习进度保持不变。

close_timeout 只限制退出时等待网络提炼的时间。取消时尝试释放任务；若取消发生在线程领取提交期间，租约到期仍可恢复。新建和恢复都先准备，再由采用成功的入口显式 activate_memory；仅写入准备条目不代表已激活，取消准备不入队、不提炼。切换会话会结束旧 worker 并重绑新存储、提炼器和模型窗口；关闭 provider 前暂停可能借用该实例的后台请求。

## 召回与主请求

每次 AgentStartEvent 从 SQLite 查询有效 preference，按完整事实装入预算（最多约 1024 估算 token，并按模型窗口缩小），保留事实 ID、来源会话/消息 ID 和日期。通用 fact 不跨会话自动注入。超大单条偏好不截成半条，本次跳过。

本轮工具循环使用固定快照；后台完成的新偏好从下一次请求开始可见。召回作为带来源的数据附在模型输入动态后缀，进入已有预算与恢复门控，不改写聊天原文、系统 prompt 或工具 schema。flush_memory 是 SDK 的显式处理/等待入口，普通聊天不会调用它等待提炼。

## 验证与边界

python -m unittest tests.memory.test_async_memory -q 使用临时 SQLite、FakeProvider 和本地 HTTP 模拟中转站；验证独立请求、同模型同接口、无工具提炼、非阻塞聊天、阈值计数、关闭恢复、配置关闭、偏好范围、工具循环固定快照、会话替换及原始证据。未使用真实用户数据库、Key 或付费 API。

自动提炼会增加模型调用量，实际提炼质量仍需用户所选模型实测。SDK 未配置独立提炼器时遵循上述默认；模型输出的字段/来源校验不能证明语义正确。未实现向量检索、事实适用范围、Web 记忆管理或远端独立 worker 服务。本次升级到 schema 6，仅给 memory_progress 增加 flush_through_seq，原有事实、任务、进度和收据保留。升级前关闭旧进程并备份 SQLite；旧版不支持 schema 6，JSONL 不能替代完整数据库备份。
