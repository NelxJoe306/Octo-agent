# 终端与话题地图

更新日期：2026-11-13（2026-11-17 注记：本文档记录话题轮次树设计及终端 `/map` 初版只读模式；`octo-web` 常驻 FastAPI 服务模式、最小聊天入口及公网鉴权边界见 [Web 服务运维说明](../../docs/web-service.md) 与 [web/README.md](../README.md)）。

## 职责

终端继续处理输入、生成、模型与凭据、推理强度和工具。Web 负责话题导航、消息查看与话题元数据操作。Python 持有运行状态和 SQLite 写入权。

`/map` 在 TUI 进程内启动可选的本机接口，附着当前 `CodingSession`；不启动第二个 Agent 或 RPC 子进程。Next.js 静态导出由该接口提供，生产运行无需独立 Node 服务。

## 请求与显示

同一会话内历史共享。进入卡片、标签或选择器会同步终端话题；定位原文只浏览对应记录，可用「在此继续」显式切换。快捷创建会原子创建并切换。

输入在异步 hook 之前冻结话题，TUI 提交也显式携带话题 ID。排队输入保留各自请求。消息开始时激活其冻结请求，后续回答与工具结果写入该请求；切换导航不会重新归因。中断后 continue 使用最后持久请求。

Harness 通过调用前接口追加当前请求的冻结话题信息，保持 system 和 tools 不变，不修改原消息。同一会话保留共享历史；已有原生压缩仍可用，完整预算门控与长期记忆策略尚未接入。话题标题是用户提供的导航数据，不能被当作新的高优先级指令。

## 持久化

SQLite schema 从 1 升到 2，保留原有会话与不可变条目，增加：

| 表 | 内容 |
| --- | --- |
| topics | 会话范围内的话题、父话题、消息锚点与标题 |
| topic_selection | 当前终端话题 |
| topic_requests | 稳定请求 ID、冻结话题 ID 与当时路径 |
| entry_requests | 原消息条目与请求的关联 |

新消息、请求与关联在同一事务内提交，重复提交幂等，归属冲突回滚。消息正文不复制也不修改。旧消息没有关联时展示在主线；旧 parent_id 不自动转换成新话题。旧分支的历史投影保持原生恢复规则。

升级后的数据库需要本版程序读取；旧版只支持 schema 1。JSONL 原文导入导出保持可用，但旧格式不携带新增话题表，完整话题恢复以 SQLite 为准。

## 本机接口

- GET `/api/snapshot`：当前会话、话题和指定话题的一页记录。
- GET `/api/anchor`：按消息 ID 定位话题和时间位置。
- POST `/api/topics`：create/select/rename；携带源 session_id，拒绝过期页面写入。
- GET `/api/events`：SSE 通知视图失效，浏览器重读快照；不发送模型 token 流。

接口只监听 127.0.0.1，通过每次启动的随机连接令牌和 Host/Origin 校验限定当前本机页面。浏览器不接收 Provider 凭据。HTTP 线程将命令交回 TUI 事件循环；话题写入与运行会话替换串行。

只读快照不创建话题或模型调用。浏览器关闭不会停止 Agent，TUI 退出关闭接口。连接恢复只重读状态，不重放写操作或用户问题。写入超时或响应丢失时，先刷新确认结果，不能认定未提交并自动重试。

## 交互与样式

复用黑色 Octo 图标、主题 token 和分隔条。树节点突出正在浏览的话题，分别标明终端当前话题与正在生成的话题。搜索展示匹配节点及其父路径，折叠和缩放仅改变显示。

工作区宽度低于 780px 时，使用树/记录页签；宽窗口树宽受 260px 下限、640px 上限及记录区 390px 预算约束。实际样式以 globals.css 和 tokens.css 为准：基础动态 0.18s、快速动态 0.14s，减少动态偏好关闭动画。界面标签不可选择，正文与输入可选择。

## 当前范围

人工命名话题；没有自动摘要、自动话题划分或 Agent 分支并发。完整压缩门控与后台记忆在后续独立实现。Plan／执行模式和子 Agent 委派已于 2026-11-14 按用户决定取消。

验收覆盖终端命令、Web 操作、A 请求生成中切到 B 的归属、排队、重启恢复、原子写入冲突和原文定位。浏览器验证使用显式标注的离线假模型会话，不代表真实模型联网测试。


## 2026-11-13 交互修订：分层树与分支标签

话题地图改为独立全宽画布。主干使用深色根节点，各深度按列排列并标出层级；父子用折线连接，同一父节点的子树分别占据独立纵向空间。保留折叠、搜索、缩放，增加适应窗口。

顶部常驻「话题地图」。从地图进入分支会打开其消息标签，重复访问复用原标签，标签关闭只影响当前窗口。关闭当前标签切换相邻标签，关闭最后一个回到地图；后台刷新不会重新打开已关闭标签。标签支持左右/Home/End 键，数量超出时横向滚动。标签状态当前仅在页面内存保存，刷新后从地图开始。

切换分支标签与进入卡片同步终端下一次输入的归属；返回地图页不切换，浏览原文仍保留「在此继续」入口。宽屏分支记录保留可调宽的树窗口，窄屏只显示当前标签内容。

验证：4 项前端行为测试、类型检查和生产构建通过；在 11 个话题的离线会话中验证分层连线、打开两个分支、重复进入去重和关闭标签。Python 运行逻辑与持久数据格式未修改。


## 2026-11-13 当前分支与续接规则（替代前述浏览/切换分离规则）

进入卡片或切换分支标签时，立即同步 Python 的当前分支；地图页本身不切换当前分支。卡片显示主干/分支编号及父分支归属。编号按创建顺序和父子层级生成，标题变化不改变编号。

主干为会话根（kind=trunk），不作为普通分支重命名；其他话题为 kind=branch。每条分支都有自己的主线，发送时从该分支最新消息继续，不沿子分支选择任何一条路径。空分支从创建锚点继续；未显式提供锚点时使用父线当时最新位置。根主干只查询根主干自己的最新消息，排除全部子分支。

请求的分支在入队时冻结，实际开始时解析该分支最新续接点，解决排队期间前一请求继续产出消息的情况。SQLite schema 3 为 topic_requests 增加 continuation_entry_id，同消息、请求和归属一并提交。全局原文日志保持线性；续接点是讨论链位置，不回退共享历史或覆盖旧记录。

后台恢复仍属于原来的未完成请求；普通新问题使用当前分支。分支编号、所属父线与当前终端位置在 Web 可见。刷新恢复以 SQLite 当前分支为准。


2026-11-13 轮次树修订：地图从上向下展开，会话主干起点在最上方。每个实心轮次节点聚合一次用户请求及其回复、工具消息，以持久 request_id 去重；多次模型调用不会拆成多个节点。节点显示本线轮次编号、提问摘要与消息数。请求续接点和消息锚点映射到所属轮次，分支连接实际起点。缺少可追踪起点的旧记录挂在会话根，不猜测旧分叉位置。

未对话分支使用“尚未开始”虚线占位，不计入轮次数。进入轮次仍同步当前分支并定位该轮消息，后续新问题沿本线最新位置继续。分支标签保持按线复用；搜索、折叠与缩放保留。预览用六轮离线示例展示连续主干和分叉，原有十一条线保留；未提交。
