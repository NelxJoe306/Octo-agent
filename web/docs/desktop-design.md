# Octo Web：页面、交互与实现设计

日期：2026-11-12。状态：已实现第一版可运行的本地交互预览；后端接入待实现。

## 1. 已确认的方向

用户要求把 TypeScript + Next.js 前端集中放在 `web/`。会话页参考用户提供的 Codex 截图；设置和控件参考本地 agentes 桌面预览。参考范围为交互与页面设计，不移植其业务模块。

Octo 保持一个主 Agent、会话内共享历史、用户手动建立话题、请求发送时冻结归属的语义。界面选择哪个话题，与模型正在回答哪个请求分别保存。话题不具备独立 Agent 或“执行完成”状态；运行状态属于请求。

按 Matt 工作流先调查参考与确定边界，再在会话 reducer 接口完成红绿测试，随后实现页面并做浏览器验证与独立双轴审查。下文的未来能力不能视为已实现。

## 3. 页面组织建议

用户最新决定：左侧保留会话列表；右侧预留对话树窗口，本轮不实现树。已实现布局：左栏默认 248px、中间弹性对话区、右栏默认 276px；两边可拖拽调宽，并为中间至少保留320px。这些尺寸是 Octo 适配值，窄窗口使用折叠/叠层。

```text
┌──────────────┬─────────────────────────┬──────────────────┐
│ Octo / 搜索  │ 会话标题                │ 对话树 · 预留窗口 │
│ 新对话       ├─────────────────────────┤                  │
│ 已置顶       │ 消息时间线              │ 仅占位说明       │
│              │                         │                  │
│ 最近对话     ├─────────────────────────┤                  │
│              │                         │                  │
│ 设置         │ 输入 / 模式 / 模型 / 发送│                  │
└──────────────┴─────────────────────────┴──────────────────┘
```

右上角按钮收起/展开右窗。实际容器宽度不足760px时左栏通过菜单打开；不足600px时右窗改为独立视图，不遮挡聊天。没有图节点、树数据或分支创建逻辑。设置以原生 `dialog` 弹出，提供通用、模型、高级三项；项目分组、设置和输入区的项目/运行环境条均已移除。模型定义由本机文件管理。

用户截图中的高级页主要借鉴设置分组、帮助提示、步进器和分段控件。并行数量、Claude Code 会话数、手机控制等业务设置不自动成为 Octo 需求。Octo 前台仍按线性请求执行，界面不能提供一个无实际执行语义的“并发主 Agent”选项。

### 4.4 需要保留的条件

- CSS 有多次同选择器定义。按钮、开关必须按后置规则和当前媒体条件分析。
- 最后一个 `@media (prefers-reduced-motion:reduce)` 在 byte 250317 的全局规则为 `transition:none!important;animation:none!important`。用户选择减少动态时，状态仍要可辨认，但不依赖动画提示。
- 折叠、选中和后台请求的执行状态不能只用颜色表达，需要文字、图标或结构标识。
- 预览在很窄的可视区会挤压设置内容；Octo 建议使用可收起导航和抽屉，保持标签和设置值可读。这是 Octo 的适配建议，不是声称参考包已经支持的行为。

### 4.5 Octo 实现建议

将经过确认的参考值集中为 CSS tokens；基础控件统一处理 default / hover / focus-visible / pressed / selected / disabled / loading 状态。React 状态、ARIA 状态和视觉状态同时更新。

分段控件第一版按参考的即时底块定位与文字色过渡实现。如果之后增加底块滑动，那是 Octo 新增设计，需要单独记录，不倒写为参考源码效果。会话切换、流式文字和话题图的动效同样需要独立确定，当前不凭参考页面推断。

## 5. TypeScript + Next.js 的实现形状

### 5.1 前后端职责

建议使用 Next.js App Router 的固定页面壳和客户端交互。Python 继续负责 Agent、文件工具、会话与 SQLite；前端不直连数据库，也不在 Next.js 中复制 Agent 主循环。

首阶段浏览器里运行桌面布局；保留后续 Electron 包装同一份页面的路径。生产构建可选静态导出，由 Python 本地服务托管静态资源，实现 UI 与接口同源；开发期使用 Next 开发服务。此托管方式是建议，尚未实现。

静态导出可由普通静态服务器托管，但不能依赖 Next 运行时能力；动态路由参数需在构建时可生成。Octo 会话 ID 在运行时产生，因此建议固定 `/` 与 `/settings/` 页面，用 query 或客户端导航状态承载会话/话题 ID。[Next.js 静态导出文档](https://nextjs.org/docs/app/guides/static-exports)

读取 query 的客户端区域按静态构建要求设置 Suspense。[useSearchParams 文档](https://nextjs.org/docs/app/api-reference/functions/use-search-params)

以后接 Electron 时，由 preload 暴露最小窗口和连接能力，页面调用同一后端接口；保持上下文隔离。[Electron Context Isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)

### 5.2 建议模块

当前实际目录：

```text
web/
  app/              layout、会话页面、全局样式
  components/       设置 dialog、Octo 图形
  lib/              会话 reducer 与行为测试
  styles/           样式变量
  docs/             设计与参考证据
  tools/            参考核对工具
```

会话 reducer 不依赖 React、计时器或网络。session/request ID 用 Zod 品牌类型，运行态使用可区分联合。定时器只发送携带 request ID 的 tick，消息写入 run.sessionId，而不是当前浏览的 activeId。停止将运行态变为空闲，迟到 tick 不再生效。页面局部导航、设置和草稿归属独立。

Next.js、React、TypeScript、Zod 与 lucide-react 的精确版本见 package.json。静态首页使用客户端状态承载会话选择；当前没有 query 路由，也没有依赖 useSearchParams。

### 5.3 行为约束（含后续真实接入目标）

- 浏览焦点 `viewedTopicId` 与当前请求冻结的 `request.topicId` 独立。流式事件按 request ID 归并，不能向当前选中页直接拼接文字。
- 草稿按会话和话题保存。生成中可以浏览别处；前台仍线性执行，请求入口与停止按钮对应实际运行请求。
- 新建会话与新建话题是两种操作，不能用一个“＋”隐式猜测。
- 用户上滚看旧消息时停止自动拉到底部，显示新内容提示；恢复跟随再滚动。
- 工具输出默认紧凑，展开查看原文与来源；长内容按 ID 分段回读，避免一次渲染整份日志。
- 设置值来自后端配置，保存失败保留草稿并说明；涉及运行中的参数需明确当前请求或下次请求生效。界面里出现的控件必须有真实配置含义。
- 流式连接以 request ID 和事件序号去重、恢复；刷新视图不启动第二次执行。进程重启后的中断状态须由后端明确处理，不能自动重放可能产生副作用的工具。

### 5.4 当前缺少的后端合同

现有 SQLite 与 RPC 能力不是已经存在的 Web API。接入真实页面前，要补会话列表/新建/消息快照接口，以及请求创建、取消和可重连事件流。话题数据、请求归属持久化及 Skill trace 也有独立前置工作。

当前预览直接使用 createPreviewState 与本地定时器驱动 reducer，尚未引入网络 adapter；真实接入时在边界解析后端事件，再转换为状态机动作。预览成功不能作为真实 Agent 闭环已实现的证据。

### 面板尺寸

`ResizeDivider` 用 Pointer Capture 固定拖拽对象，左栏向右拖增加宽度、右栏向左拖增加宽度。左右范围分别为 192–420px 与 220–480px，并根据容器和另一栏的宽度收紧上限；当前聊天最小宽度为320px。拖动时禁用网格过渡，避免指针与面板错位。方向键每次8px，Shift加速为32px，Home/End到边界，双击恢复默认。响应式模式以实际容器宽度判定，见第10节；已撤销900px右窗叠层规则。宽度当前不跨刷新保存。

### 本机模型配置

由 `useLocalModels` 管理已解析模型、编辑草稿、文件来源与IO状态；`lib/models.ts` 定义唯一配置schema。文件直接由浏览器的文件选择器读取/写回，不请求服务器或持久到浏览器存储。文件授权不自动恢复，刷新需重新打开。

配置字段：version、defaultModelId、models；每个模型必须有唯一id、name和provider，可选baseUrl及reasoning。能力声明包含允许的value/label与default；校验重复ID、重复强度、无效默认值与非HTTP地址。页面不能依据模型名字猜能力。

文件保存前比较原始内容，外部修改时拒绝覆盖并提示重新读取。写入失败abort，保留编辑内容和原异常；IO期间冻结编辑、示例、导入和应用入口，避免保存旧快照吞掉新输入。不支持文件句柄时走原生文件导入、显式下载链接导出；修改草稿使旧URL立即失效，替换/卸载回收URL。

「应用到预览」明确不落盘；「保存配置文件」用于真实文件保存。配置只包含模型定义，当前没有凭据读取、模型调用或Python配置接线。

### 模型选择与文字选择

选择器为自定义浮层，显示name、provider、id与选中勾号，支持搜索；选中支持reasoning的模型才显示其允许的推理强度。普通模型清除强度，重新选择同一模型保留已选强度。失效模型回退配置默认或首项。

应用界面默认user-select:none；`.message-text`、输入框、textarea、代码与日志允许user-select:text。导航、品牌、按钮、状态文案不进入鼠标文本选择。

### 验证与限制

三项测试覆盖既有会话状态以及模型解析/能力切换/非法配置，类型检查通过。浏览器实测左右拖拽与键盘调整、配置应用、模型搜索与名称显示、仅推理模型出现强度、普通模型取消强度，以及正文/输入可选与导航不可选的计算样式。保存期间冻结编辑和写入失败abort经过独立审查验证。

内置浏览器未完成原生文件选择器的落盘闭环验证，不能把页面配置应用成功写成文件读写已实测。真实模型调用、认证、跨刷新自动读取及与Python共用文件加载仍未实现。


## 10. 窗口尺寸适配修复

问题已在820×643的真实页面复现：900px媒体规则把右窗改成absolute，而右窗收起逻辑只在mount运行；从大窗口缩小后，右窗盖在聊天与输入框上。修复前边界检查得到chat.right=811、tree.left=591，inputCovered=true；修复后同尺寸chat.right=tree.left=577，遮挡和输入越界均false。

布局预算集中在 `lib/layout.ts` 的 `fitWorkspace`，输入为ResizeObserver测得的容器实际宽度、偏好栏宽和右窗开关；React通过data-layout与CSS变量消费结果，取消右窗悬浮覆盖规则，避免CSS视口断点与JS初始化状态各做判断。

| 实际容器宽度 | 布局行为 |
| --- | --- |
| 至少760px | 左列表、聊天、右窗并排；两边可拖宽，聊天至少320px |
| 600–759px | 左栏为带遮罩的抽屉；聊天与右窗仍各占一列，右窗可拖宽 |
| 不足600px | 缩小时自动收起右窗；手动打开时右窗成为独立视图，聊天隐藏并inert；“返回对话”恢复聊天 |

从窄窗对话树选会话或新建会话时，自动切回聊天。Ctrl+K同时展开抽屉并聚焦搜索；新建会话在解除workspace的inert后聚焦输入框。抽屉支持Escape、焦点约束和点击遮罩关闭。

垂直适配：移除app的460px最小高度及空状态的180px最小高度；低于600px高时减小头部、Logo及输入区间距，低于380px高时收起次要提示。空状态字号依据聊天容器宽度变化；模型浮层限制在视口可用高度内，列表独立滚动。

验证：原始浏览器边界断言先失败后通过；连续检查1440×900、1024×700、820×643、700×500、390×600、320×480、600×320，均无左右遮挡、输入底部越界或页面水平溢出。另验证窄窗右视图返回、会话选择、Ctrl+K搜索与新建焦点，以及右栏尺寸上限。4项单元测试、TypeScript检查与生产构建通过。独立双轴审查提出的窄窗导航和焦点问题已修复、复核关闭。未commit。
