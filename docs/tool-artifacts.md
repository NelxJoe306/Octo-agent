# 持久工具产物：最小实现

用户已确认：完整工具文本持久化；主请求只带短预览和 artifact ID；按 ID 有界回读；恢复同一会话后仍可读取。沿用终端主入口、SQLite 权威存储、原始消息不可改写和当前轮完整工具块保护。

## 接口与接入

- `ToolArtifactStore.put(call, text, request=None, is_error=False)` 保存文本和冻结来源，返回稳定引用；`read(id, offset=0, limit=2048)` 限制为最多 4096 UTF-8 字节，仅查询当前会话。
- 原文以 UTF-8 BLOB 保存在 SQLite schema 4 的 tool_artifacts 表（支持 NUL 和有界字节读取），引用含校验值、字符数、UTF-8 字节数、工具调用与请求/话题身份。提交完成后才返回 ID；同一调用、冻结来源、内容及错误状态重复保存得到同一 ID。
- 会话的 after_tool_call 在下一轮预算门控之前处理最终工具结果。超过 8192 UTF-8 字节的文本以 1024 字节的首尾预览代替；图片块、工具调用 ID 和错误状态保留。先持久原文，后产生带引用的新 tool_result，不重写既有消息。
- SQLite 会话始终提供 read_artifact，schema 不随产物数量变化。同名扩展替换会被忽略并给出诊断，读取工具仍经过全局扩展钩子。非 SQLite 使用原有工具行为。资源重载、新建/恢复会话重新绑定正确的存储与执行钩子。
- Bash 在受管会话中把截断前文本暂交给结果处理，不再只依赖临时日志；独立 Bash 调用和终端手工命令保持原有临时文件行为。扩展显式替换结果文本时尊重扩展结果。
- 读取结果自身有大小上限，不再次外置成新产物。保存失败不返回伪造的 ID，要明确说明工具已执行但输出未能持久化。

## 验收入口（沿用用户确认场景）

1. 持久存储公开接口：文本重启后精确读取中段、ID 幂等、Unicode、越界/错误 ID、会话隔离、来源信息。
2. CodingSession.prompt：超长本轮工具结果不再堵住下一次主调用；模型能通过 read_artifact 回读中段；调用/结果对应与错误标记保持。
3. 原生 Bash：实际输出超过旧截断上限，完整内容在持久库，下一轮只有预览。恢复/新建会话与资源重载不错误绑定旧存储。
4. 会话压缩：压缩只改变本次模型输入，已保存 ID 继续可读；不承诺摘要自动记住全部历史 ID。

本阶段不增加 Web 产物页面、搜索、自动清理、输出流式采集或长期记忆。使用现有 FakeProvider 与真实临时 SQLite/子进程测试，不调用付费 API。


## 存储升级与边界

数据库升级到 schema 4，仅增加不可改写的 tool_artifacts 表；原会话和话题表不变。旧版二进制无法打开 schema 4，首次运行新版前应关闭旧进程并备份会话库，或使用 SQLite backup。JSONL 导出不携带产物 BLOB，完整备份需要保留 SQLite 库。

回读参数的 offset/limit 使用 UTF-8 字节；offset 在字符中间时向后对齐到下一个完整字符，next_offset 给出下一段的可靠位置。返回正文最多 4096 字节，另有固定大小的来源头。取消时未返回的保存可能留下无引用产物，但不会给模型一个尚未提交的 ID；本阶段不自动清理。

受管 Bash 完整输出、通用大文本工具结果和 read_artifact 已接入会话主循环；本机独立调用与手工终端命令仍沿用原行为。既有历史工具结果与旧临时日志不自动迁移，摘要也不保证自动保留全部历史产物 ID；完整 ID 可从持久工具记录找回。
